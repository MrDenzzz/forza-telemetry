# 0006. API истории: REST-ресурсы только для чтения, типизированные общими контрактами

[English](0006-history-rest-api.md) · **Русский**

- Статус: принято
- Дата: 2026-10-02

## Контекст

Веб-приложение показывает список сессий, сессию с её кругами и графики сравнения двух кругов. Позже то же может показывать мобильное приложение. Экранов мало, и они фиксированы; единственный большой ответ — трасса круга, около 50 КБ чисел. ТЗ допускало REST или GraphQL.

## Решение

- **REST с тремя ресурсами только для чтения:**
  - `GET /sessions?cursor&limit&kind`: сессии, новые первыми, постранично;
  - `GET /sessions/:id`: одна сессия со сводками её кругов;
  - `GET /laps/:id`: один круг с заголовком его сессии и полной трассой.
- **Схемы лежат в `@ft/contracts`** (zod), как и схемы live-потока. Query-параметры и id в пути проверяются ими в Nest-пайпе; некорректный запрос получает 400 с сообщением zod. Обработчики возвращают типы контрактов, а e2e-тесты разбирают каждый ответ этими схемами.
- **Курсорная пагинация.** Курсор — id последней сессии на странице; порядок — по `startedAt` по убыванию, затем по `id`, с индексом по обоим полям. Пока API записывает, новые сессии добавляются в начало, и курсор от этого не сдвигается, в отличие от смещения.
- **Круг кешируется навсегда** (`Cache-Control: public, max-age=31536000, immutable`), потому что записанный круг никогда не меняется ([ADR 0005](0005-session-storage.ru.md)). Заголовок ставится в обработчике после того, как круг найден, а не через `@Header`: Nest применяет его до вызова обработчика, и он попал бы и в ответ 404.
- **Те же единицы, что в live-потоке:** м/с, метры, секунды, g; метки времени в ISO 8601 UTC. Сессия, которая ещё идёт, приходит с `endedAt: null`.
- **Ни записи, ни аутентификации.** API отдаёт историю одного игрока; через него ничего не удаляется и не редактируется.

## Последствия

- Сравнение двух кругов — это два запроса, каждый кешируется отдельно, и однажды загруженный круг больше не нужно загружать.
- Клиенты обрабатывают идущие сессии и прерванные сессии, у которых статистика равна null.
- Документация — это контракты; описания OpenAPI нет. Его можно сгенерировать из схем zod, если появится сторонний клиент.
- Добавление поля обратно совместимо; переименование меняет контракт, с которым компилируются и веб, и API, поэтому оба не соберутся, пока не придут к согласию.

## Рассмотренные альтернативы

- **GraphQL.** Позволяет каждому экрану выбирать поля, но экраны фиксированы, а он приносит схему, резолверы, клиентскую библиотеку и кеширование на уровне запросов там, где URL на каждый круг даёт HTTP-кеширование бесплатно.
- **tRPC.** Типобезопасность без собственной схемы, но каждый клиент привязывается к TypeScript-типам и транспорту сервера; контракты на zod поверх обычного HTTP дают ту же безопасность и доступны из чего угодно.
- **Пагинация по смещению.** Проще, но страницы сдвигаются, когда записываются новые сессии.
- **Один эндпоинт, отдающий оба круга сравнения.** Экономит запрос, но каждая пара кругов становится отдельной записью в кеше.
