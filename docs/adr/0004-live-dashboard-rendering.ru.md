# 0004. Рендеринг live-дашборда: внешний store, примитивные селекторы, canvas

[English](0004-live-dashboard-rendering.md) · **Русский**

- Статус: принято
- Дата: 2026-10-02

## Контекст

Дашборды получают полный кадр до 30 раз в секунду. Если бы каждый кадр становился React-состоянием наверху дерева, весь дашборд согласовывался бы 30 раз в секунду, а в мобильном браузере это заметно по пропущенным кадрам и расходу батареи. Графики добавляют своё: 30 секунд истории — это около 900 точек на серию. Та же логика подключения и состояния понадобится ещё раз в приложении на React Native.

## Решение

- **Store, не зависящий от фреймворка,** в `@ft/live-client`, общий с мобильным приложением. В нём два отдельных набора подписчиков: один для статуса подключения, который меняется несколько раз за сессию, другой для кадров.
- **React читает его через `useSyncExternalStore`.** Компоненты, зависящие только от статуса, никогда не перерисовываются из-за кадров. Значения из кадра читаются через `useFrameValue(select)`, где `select` возвращает примитив, уже округлённый для показа: целые км/ч, обороты шагами по 25 об/мин, температура шин в целых градусах. Компонент перерисовывается только тогда, когда меняется показываемое им число, а не когда приходит кадр.
- **Canvas для высокочастотной графики.** Круг перегрузок рисуется императивно, не чаще раза за кадр анимации. Графики построены на uPlot, который получает данные из кольцевого буфера store через `setData` в `requestAnimationFrame`. React рендерит эти компоненты один раз.
- **Кольцевой буфер фиксированного размера** хранит историю для графиков: окно, умноженное на максимальную частоту кадров, с вытеснением по времени, поэтому добавление кадра никогда не выделяет память.
- **Переподключение** с экспоненциальной задержкой и джиттером; `hello` с другой версией протокола останавливает попытки и сообщает об этом.

## Последствия

- Решение охраняют два теста: компоненты, зависящие только от статуса, не перерисовываются, когда приходят 30 кадров (мутация, при которой каждый кадр будит подписчиков статуса, роняет этот тест), и значение из кадра не перерисовывается, если показываемое число не изменилось.
- Селекторы должны возвращать примитивы или ссылки, стабильные между кадрами; новый объект вызывал бы перерисовку на каждом кадре.
- Содержимое canvas не видно вспомогательным технологиям, поэтому у каждого canvas есть роль и подпись, а числовые показания оформлены подписанными группами, а не `<output>`: его неявный live region зачитывал бы каждый кадр.
- uPlot импортируется только в браузере, внутри эффекта, потому что обращается к DOM при импорте.

## Рассмотренные альтернативы

- **Кадры как React-состояние или контекст.** Просто, но всё поддерево согласовывается на каждом кадре.
- **Zustand или Redux с селекторами.** Дают ту же выборочную перерисовку, но добавляют зависимость ради примерно шестидесяти строк store, который к тому же должен без изменений работать в React Native.
- **Графики на SVG или DOM** (Recharts и подобные). Каждая точка — DOM-узел, который согласовывает React; при 30 обновлениях в секунду и сотнях точек это не выдерживает нагрузки.
- **WebGL.** Больше возможностей, чем нужно для двух линейных графиков и точки.
