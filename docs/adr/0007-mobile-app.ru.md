# 0007. Мобильное приложение: Expo Go, приборы на shared values

[English](0007-mobile-app.md) · **Русский**

- Статус: принято
- Дата: 2026-10-03

## Контекст

Телефон должен стоять рядом с экраном как горизонтальный дашборд. Он показывает те же live-данные, что и веб-дашборд, и сам переподключается. Кадры приходят до 30 раз в секунду, а экраны телефонов обновляются с частотой 60 или 120 Гц, поэтому стрелка, которая прыгает раз за кадр, выглядит грубо. Любой, кто захочет попробовать проект, должен запустить приложение без сборки нативного кода. Логика подключения и store уже есть в `@ft/live-client`.

## Решение

- **Expo SDK 57, запуск в Expo Go.** Reanimated 4 и Skia 2 уже встроены в Expo Go, поэтому нативная сборка не нужна: хватает `expo start` и QR-кода. Нативные сборки остаются возможны позже через `expo prebuild` или EAS.
- **Сначала общий код.** Приложение берёт из `@ft/live-client`:
  - подключение и переподключение;
  - store;
  - тексты статусов, правила отображения и геометрию перегрузок, перенесённые туда из веб-дашборда.

  Metro читает исходники пакета на TypeScript через условие экспорта `@ft/source`, как и весь монорепо.

- **Два пути обновления, как в вебе** ([ADR 0004](0004-live-dashboard-rendering.ru.md)):
  - **Числа** берутся через `useFrameValue` и перерисовываются только при изменении показываемого значения.
  - **Графика не перерисовывается вовсе.** Подписчик на кадры записывает shared values Reanimated на JS-потоке. UI-поток читает их:
    - Skia рисует дугу тахометра (обрезанный путь) и след перегрузок (путь, который пересобирается в derived value);
    - стили Reanimated масштабируют полосы педалей и сцепления.
- **Показания плавно переходят.** Стрелка тахометра и педали анимируются к каждому новому значению примерно за один кадр потока, поэтому движутся непрерывно при любой частоте экрана.
- **Горизонтальная ориентация в обе стороны.** `app.json` фиксирует горизонтальную ориентацию, а `expo-screen-orientation` позволяет повернуть телефон любой стороной.
- **Батарея и ресурсы.**
  - В фоне сокет закрывается, при возврате открывается снова.
  - Экран не гаснет, только пока идёт езда.
- **Экран подключения угадывает адрес API.** В разработке `Constants.expoConfig.hostUri` — это компьютер, который отдаёт бандл, и API обычно работает на нём же. Адрес разбирается без `URL`, чья реализация в React Native давно неполная.
- **Jest для этого пакета.** Expo поддерживает Jest (`jest-expo`) и React Native Testing Library; остальной репозиторий тестируется на Vitest. Тесты проигрывают скриптованный поток, общий с тестами веба (`@ft/live-client/testing`), подменяют нативный модуль Skia заглушкой и запускают Reanimated на JS-потоке. CI собирает бандлы приложения через `expo export` для обеих платформ.

## Последствия

- Приложение привязано к тому, что Expo Go поставляет для SDK 57: React 19.2, тогда как веб использует 19.3. pnpm ставит обе версии рядом.
  - **Metro** отдаёт каждому пакету React приложения, потому что в монорепо Expo включает свой резолвинг модулей.
  - **Jest** нужно указать то же через `moduleNameMapper`.
  - SDK 58, который скоро выйдет, переходит на React 19.3.
- **Отрисовка приборов не покрыта тестами.** Её проверяют на устройстве, а стоящая за ней геометрия проверяется тестами как числа.
- **Незашифрованный `ws://` в локальной сети.** В Expo Go он работает. Релизной сборке понадобятся `usesCleartextTraffic` на Android и описание доступа к локальной сети на iOS; описание уже есть в `app.json`.
- **ESLint использует общий React-пресет**, а не `eslint-config-expo`: входящий в него `eslint-plugin-react` не поддерживает ESLint 10.

## Рассмотренные альтернативы

- **Development build с нативным кодом.** Позволяет любой нативный модуль, но каждому, кто смотрит проект, пришлось бы собирать или ставить бинарник. Здесь не нужно ничего сверх того, что даёт Expo Go.
- **Перерисовка приборов через состояние React.** Проще, но согласовывает дерево приборов 30 раз в секунду на JS-потоке, который делит с WebSocket.
- **Приборы на SVG (react-native-svg).** Декларативно, но перерисовывается через React; для анимации нужен `createAnimatedComponent` на каждой фигуре, а длинные пути рисуются медленнее, чем в Skia.
- **Запись shared values без плавного перехода.** Корректно, но на экране 120 Гц стрелка заметно шагает с частотой 30 Гц.
