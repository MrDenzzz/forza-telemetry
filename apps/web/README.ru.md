# @ft/web

[English](README.md) · **Русский**

Приложение на Next.js из двух частей:

- **Live** (`/`): скорость и передача, обороты, педали и руль, перегрузки, температура и сцепление шин, позиция в гонке и время кругов, а также 30-секундные графики скорости, оборотов, газа и тормоза.
- **История** (`/sessions`): записанные сессии со статистикой и кругами и сравнение любых двух кругов (`/compare?laps=a,b`): разрыв по времени, скорость, газ, тормоз и передача по ходу круга, с картой трассы, которая следует за курсором.

```sh
pnpm dev    # из корня репозитория: API на :4000 и дашборд на http://localhost:3000
```

| Переменная                   | По умолчанию            | Значение                                                                                                                                   |
| ---------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `NEXT_PUBLIC_API_URL`        | `http://localhost:4000` | Базовый URL API; адрес live-потока выводится из него (`http` → `ws`, `https` → `wss`)                                                      |
| `API_URL`                    | `NEXT_PUBLIC_API_URL`   | API, каким его видит сервер, для истории и трассы проигрываемого заезда, если адрес отличается от публичного (в Docker: `http://api:4000`) |
| `NEXT_PUBLIC_DEMO_MEDIA_URL` | `/media/demo`           | Где страница демо берёт видео, постер и дорожку телеметрии ([docs/deploy.ru.md](../../docs/deploy.ru.md#3-медиа-демо))                     |

Адреса API читаются и проверяются на сервере при рендере страниц, поэтому один образ подходит для любого домена; некорректный URL роняет страницы, которые его используют, с ошибкой валидации. Браузер открывает только live-поток, всё остальное запрашивает сервер. Страница демо статическая, поэтому адрес её медиа фиксируется при сборке: значение по умолчанию — путь на том же сайте — подходит для любого домена.

## Как устроен рендеринг

Кадры приходят до 30 раз в секунду, и страница не перерисовывается на каждый из них: числа читаются через селекторы, которые перерисовывают компонент только при изменении показываемого значения, а круг перегрузок и графики рисуются на canvas раз за кадр анимации. Подробности и альтернативы: [ADR 0004](../../docs/adr/0004-live-dashboard-rendering.ru.md).

Подключение, store и React-хуки берутся из [`@ft/live-client`](../../packages/live-client/README.ru.md), которым пользуется и мобильное приложение.

Страницы истории — серверные компоненты: они получают данные из [REST API](../../apps/api/README.ru.md#интерфейс), проверяют каждый ответ общими контрактами и отдают HTML. Сессии запрашиваются каждый раз заново, а круги кешируются навсегда, потому что записанный круг не меняется. В браузере работают только интерактивные части: выбор кругов и графики сравнения, курсоры которых синхронизированы и двигают метку на карте трассы без перерисовки React.

Круги сравниваются точка в точку, потому что каждая трасса записана в одних и тех же местах маршрута; расстояние на графиках отсчитывается по первому кругу.

## Тесты

Vitest с Testing Library в happy-dom: форматирование, конфигурация, геометрия круга перегрузок, виджеты на фейковом WebSocket, график с замоканным uPlot и подсчёт рендеров, доказывающий, что кадры не перерисовывают компоненты, зависящие только от статуса. Для истории: клиент API на фейковом `fetch` (проверка контрактом, 404, ошибки), математика сравнения, таблицы сессий и кругов, выбор кругов и метка на карте трассы.
