# @ft/recording

[English](README.md) · **Русский**

Формат файла для сырых записей телеметрии и планировщик, который воспроизводит их с исходным таймингом. На нём построены CLI recorder и replayer и демо-режим API. Только для Node.js.

## Формат

Little-endian, версия 1. Файлы с расширением `.gz` прозрачно сжимаются gzip.

| Часть     | Структура                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------ |
| Заголовок | магические байты `FZTR`, версия формата `U16`, длина метаданных `U32`, метаданные в JSON (UTF-8) |
| Запись    | миллисекунды с начала записи `F64`, длина payload `U16`, сырая UDP-датаграмма                    |

В метаданных хранятся игра (`fh5` или `fh6`), время начала записи и необязательная заметка. Почему выбран такой формат: [ADR 0002](../../docs/adr/0002-recording-format.ru.md).

## API

| Экспорт                                 | Назначение                                                                                                     |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `createRecordingWriter(path, metadata)` | Возвращает `write(packet)` и `close()`. Создаёт недостающие каталоги.                                          |
| `readRecordingMetadata(path)`           | Читает только заголовок.                                                                                       |
| `readRecordedPackets(path)`             | Асинхронный итератор пакетов. Неполная запись в конце файла, оставшаяся от прерванного recorder, пропускается. |
| `RecordingDecoder`                      | Инкрементальный декодер: принимает файл кусками любого размера.                                                |
| `replay(openPackets, emit, options)`    | Отдаёт пакеты с исходными интервалами; параметры `speed`, `loop`, `signal` и подменяемые часы `clock`.         |

`replay` отсчитывает время каждого пакета от начала прохода, а не от предыдущего пакета, поэтому запаздывание таймеров (в Windows до ~16 мс) не накапливается в дрейф. Тесты гоняют его на фейковых часах, без реального ожидания.
